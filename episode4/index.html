🎤 구산구 AI 혁명기

Episode 4: 데이터 전쟁

소설 본문

"과장님, 문제가 생겼습니다."

민준은 박소희 앞에 예산 집행 현황표를 펼쳤다. 빨간 글씨로 가득했다.

"복지 예산이 이미 80% 집행됐어요. 하지만 아직 분기가 두 달이나 남았고요."

박소희는 한숨을 쉬었다.

"원래 그래요. 구산구는 항상 예산이 부족해요. 특조 예산 신청해도 6개월은 걸리고..."

"6개월이요? 그동안 발견한 사각지대 30명은요?"

"...기다려야죠."

민준은 노트북을 켰다. 구산구청 전체 예산 집행 현황을 확인했다. 복지과는 80% 집행, 하지만 지역경제과는 35%, 문화체육과는 28%만 집행되어 있었다.

"과장님, 타 부서 예산 중 연말까지 집행 안 될 것 같은 건 우리가 쓸 수 있지 않을까요?"

"그건... 예산 전용이라고 해서 조례에 명시되어 있어야만 가능해요. 수백 페이지 조례를 다 뒤져야 하는데..."

민준은 안경을 밀어 올렸다.

"제가 해볼게요."

오후 2시. 민준은 구산구청 홈페이지에서 조례집 PDF 30개를 다운로드했다. 총 1,200페이지. 이걸 일일이 읽으면 일주일은 걸린다.

'하지만 ChatGPT한테는...'

그는 ChatGPT를 켰다. 하지만 문제가 있었다. PDF를 직접 업로드할 수는 있지만, 30개 파일을 한 번에 처리하기는 어려웠다.

'검색 기능이 필요해.'

민준은 웹을 검색했다. 'ChatGPT 문서 검색', 'RAG', 'Retrieval-Augmented Generation'... 생소한 용어들이 나왔다.

30분 후, 민준은 개념을 이해했다.

'RAG는... AI가 방대한 문서를 검색하고, 관련 부분만 찾아서 답변하는 거구나.'

그는 ChatGPT에 첫 번째 조례 PDF를 업로드했다.

너는 구청 기획예산과 법무 담당자야. 업로드된 조례를 분석해서, "복지예산을 타 부서 예산으로 전용할 수 있는 조항"이 있는지 찾아줘. 있다면: - 조항 번호 - 조건 - 절차 를 명확히 알려줘. 없다면 "해당 조항 없음"이라고만 답해.

엔터를 눌렀다. 10초.

해당 조항 없음

민준은 두 번째 파일을 업로드했다. 세 번째, 네 번째... 17번째 파일까지 "해당 조항 없음"이 반복됐다.

그리고 18번째 파일.

발견: 조항: 구산구 예산 및 기금 운용 조례 제28조 3항 내용: "긴급 복지 수요 발생 시, 타 부서 미집행 예산 중 연말까지 집행 불가 확실한 예산을 복지정책과로 전용 가능" 조건: 1. 복지정책과장 신청 2. 기획조정국장 승인 3. 구의회 사후 보고 (30일 이내) 절차: 전용신청서 → 국장 결재 → 즉시 집행 가능

민준은 화면을 뚫어지게 바라봤다. 손이 떨렸다.

"있었어..."

오후 4시. 민준은 최태양 국장실로 달려갔다. 박소희도 함께였다.

"국장님, 방법을 찾았습니다."

민준은 조례 제28조 3항을 출력해서 보여줬다.

"지역경제과와 문화체육과 미집행 예산 중 약 5억 원을 복지과로 전용할 수 있습니다."

최태양은 서류를 읽었다. 표정이 굳었다.

"이거... 진짜야?"

"네. 제가 조례 1,200페이지를 전부 검토했습니다."

"에휴... 이 조항이 20년 전에 만들어진 거라 아무도 몰랐어. 나도 처음 봐."

최태양은 팔짱을 꼈다.

"하지만 문제가 있어. 타 부서가 가만있겠어?"

"국장님 결재만 있으면 됩니다. 조례상으로는."

"조례상으로는 그래. 하지만 실제로는... 지역경제과 과장이 날 죽일 거야."

박소희가 끼어들었다.

"국장님, 하지만 복지 사각지대 30명이 기다리고 있어요."

최태양은 한참을 고민하더니 한숨을 쉬었다.

"좋아. 내가 책임질게. 서류 준비해."

다음 날 아침. 예산 전용 소식이 퍼졌다. 지역경제과 김성호 과장이 복지정책과로 찾아왔다.

"박 과장, 이게 무슨 짓이야?"

김성호는 얼굴이 벌겋게 달아올라 있었다.

"우리 예산 3억을 빼 간다고? 우리도 쓸 데가 있어!"

박소희는 침착하게 대답했다.

"김 과장님, 이건 미집행 예산이에요. 연말까지 집행 안 되면 반납해야 하잖아요."

"그건 우리가 알아서 해! 왜 복지과가 간섭해?"

"조례 제28조 3항에..."

"조례? 20년 된 조례를 지금 꺼내? 이건 꼼수야!"

민준이 일어섰다.

"과장님, 이건 법적으로 정당한 절차입니다. 국장님 결재도 받았고요."

"당신 누구야? 청담구에서 온 애가 여기서 뭘 안다고?"

민준은 입술을 깨물었다. 김성호는 박소희를 노려봤다.

"박 과장, 이거 두고 봐. 다음 부서장 회의에서 다시 이야기하자."

쿵. 문이 닫혔다.

오후 3시. 부서장 회의. 10명의 과장들이 모였다. 최태양 국장이 앞에 섰다.

"오늘 안건은 복지정책과 예산 전용 건입니다."

김성호가 손을 들었다.

"국장님, 이건 부당합니다. 우리 지역경제과는 하반기 소상공인 지원 사업이 남았어요."

문화체육과 이명희 과장도 거들었다.

"우리도 마찬가지예요. 연말 문화 행사 예산인데, 이걸 빼 가면 주민들한테 뭐라고 설명해요?"

박소희가 일어섰다.

"두 분 과장님, 집행률 보셨죠? 지역경제과 35%, 문화체육과 28%. 6개월 남았는데 60% 이상을 집행할 수 있나요?"

"그건... 사업 일정상..."

"복지정책과는 지금 당장 도움이 필요한 사람들이 30명 대기 중입니다. 이분들은 하루하루가 급해요."

회의실이 조용해졌다. 최태양이 끼어들었다.

"조례상 절차는 정당합니다. 하지만 이견이 있으니, 제가 절충안을 내겠습니다."

최태양은 화이트보드에 숫자를 적었다.

"지역경제과 3억 → 2억으로 축소. 문화체육과 2억 → 1억으로 축소. 복지정책과는 3억만 확보. 어떻습니까?"

김성호는 불만스러웠지만 고개를 끄덕였다.

"...그럼 그렇게 하죠."

회의가 끝나고. 민준은 책상에 앉아 있었다. 3억. 목표했던 5억의 60%였지만, 그래도 성공이었다.

박소희가 다가왔다.

"민준 씨, 고생했어요. 김 과장님 화나신 거 신경 쓰지 마세요."

"...괜찮습니다."

"조직 생활이 원래 그래요. 누군가 이득을 보면 누군가는 손해를 보게 돼 있어요."

민준은 고개를 들었다.

"과장님, 제가 한 게 맞는 걸까요? 법적으로는 맞지만... 다른 부서 사람들이 원망하잖아요."

박소희는 민준의 어깨를 두드렸다.

"민준 씨가 한 건 데이터를 찾은 거예요. 결정은 국장님이 하셨고. 민준 씨는 도구를 제공한 거죠."

"하지만 다른 부서 사람들이..."

"알아요. 하지만 생각해봐요. 민준 씨는 조례를 찾았을 뿐이에요. AI처럼요."

민준은 고개를 들었다.

"AI처럼요?"

"네. AI는 답을 주지만, 어떻게 쓸지는 사람이 결정하잖아요. 민준 씨가 찾은 조례도 마찬가지예요. 도구를 제공했을 뿐, 사용 방법은 국장님이 결정하신 거죠."

민준은 고개를 끄덕였다.

💡 Tutorial: RAG (Retrieval-Augmented Generation) 이해하기

민준이 사용한 기술: RAG 개념을 활용한 문서 검색

1. Logic (원리)

문제 상황:

- 1,200페이지 조례를 일일이 읽는 건 불가능

- ChatGPT는 대화 기록만 기억하지, 외부 문서는 자동으로 검색 못함

- 필요한 정보가 방대한 문서 속 어딘가에 숨어 있음

RAG란?

RAG는 Retrieval(검색) + Augmented(강화) + Generation(생성)의 약자입니다.

쉽게 말하면:

1. Retrieval: AI가 방대한 문서에서 관련 부분을 검색

2. Augmented: 검색된 내용을 AI에게 추가로 제공

3. Generation: AI가 검색 결과를 바탕으로 답변 생성

비유:

- 일반 ChatGPT = 암기만 하는 학생

- RAG = 필요할 때 책을 찾아보는 학생

2. Stack (도구)

초급 방법 (민준이 사용한 방식):

- ChatGPT 유료 버전 (GPT-4)

- PDF 업로드 기능 활용

- 한 번에 1~2개 파일 처리

한계:

- 30개 파일을 동시에 검색 불가

- 파일마다 반복 업로드 필요

중급 방법 (추후 학습):

- Custom GPT + 파일 여러 개 업로드

- 여러 문서를 동시에 검색 가능

고급 방법 (전문가용):

- LangChain, LlamaIndex 등 RAG 전용 라이브러리

- 자체 검색 시스템 구축

3. Guide (실행)

Step 1: 문서 준비

좋은 문서 형식:

- PDF, DOCX, TXT

- 명확한 제목, 목차, 페이지 번호

- 검색 가능한 텍스트 (이미지 PDF는 X)

나쁜 문서 형식:

- 스캔본 이미지 (텍스트 인식 안 됨)

- 암호화된 PDF

- 너무 큰 파일 (100MB 이상)

Step 2: 검색 질문 설계

민준의 프롬프트 분석:

너는 구청 기획예산과 법무 담당자야. [역할] 업로드된 조례를 분석해서, [작업] "복지예산을 타 부서 예산으로 전용할 수 있는 조항"이 있는지 찾아줘. [목표] 있다면: - 조항 번호 - 조건 - 절차 를 명확히 알려줘. [출력 형식] 없다면 "해당 조항 없음"이라고만 답해. [없을 때 처리]

핵심 포인트:

- ✅ 구체적인 검색 대상 명시

- ✅ 발견 시 필요한 정보 나열

- ✅ 미발견 시 간결하게 처리

Step 3: 결과 검증

ChatGPT가 찾은 조항을 반드시 원본 문서에서 재확인하세요.

검증 방법:

1. 조항 번호로 원본 PDF 검색 (Ctrl+F)

2. 전후 문맥 확인

3. 다른 조항과 충돌 여부 확인

민준의 실수 방지:

- AI가 없는 조항을 "만들어낼" 수 있음 (환각 현상)

- 반드시 원본 확인 필수!

4. 실전 응용

응용 1: 계약서 검토

상황: 50페이지 계약서에서 "위약금 조항" 찾기

너는 법무팀 계약 담당자야. 업로드된 계약서에서 위약금 관련 조항을 모두 찾아줘. 각 조항마다: - 조항 번호 - 위약금 비율 - 발생 조건 을 정리해줘.

응용 2: 회의록 검색

상황: 6개월치 회의록에서 "AI 도입 논의" 찾기

너는 기획팀 주무관이야. 업로드된 회의록들에서 "AI 도입"이 논의된 회의를 찾아줘. 각 회의마다: - 날짜 - 핵심 논의 내용 - 결정 사항 을 요약해줘.

응용 3: 연구 논문 리뷰

상황: 100페이지 논문에서 "연구 방법론" 추출

너는 대학원 연구원이야. 업로드된 논문에서 연구 방법론 부분을 찾아서, - 연구 설계 - 데이터 수집 방법 - 분석 기법 을 정리해줘.

5. 주의사항

❌ 하지 말아야 할 것:

1. AI 답변을 검증 없이 그대로 사용

2. 민감한 개인정보가 담긴 문서 업로드

3. 저작권 보호된 문서 무단 업로드

✅ 해야 할 것:

1. 항상 원본 문서로 재확인

2. 중요한 결정은 사람이 최종 판단

3. 문서 보안 정책 준수

6. RAG의 한계

ChatGPT PDF 업로드 방식의 한계:

- 한 번에 1~2개 파일만 처리

- 파일 크기 제한 (보통 50MB)

- 복잡한 표, 그래프 인식 어려움

극복 방법:

- Custom GPT: 여러 파일 동시 검색

- 전문 RAG 도구: 더 정교한 검색

- 사람의 최종 검증: AI는 보조, 판단은 사람
